# R-149 (Security QA): مصفوفة تغطية الأمن واختبارات الانحدار

> تجرد تغطية الأمن كما طلبت مهمة R-149: كل ضمان مربوط بالاختبار الذي يثبته **فعليًا** — بالـassertions الحاسمة لا بأسماء الاختبارات — مع حدود الإثبات، ثم الفجوات المثبتة التي أغلقتها هذه الدفعة والتسريبات الثلاث التي اكتُشفت وأُصلحت. الفئات مرتبطة بمتطلبات مهمة R-149 (تقرير التدقيق الخارجي الأصلي لم يُعثر عليه في المستودع — لم تُنسب إليه صفوف). خط الأساس: main بعد PR #155 (`d224652`)؛ الفرع `m7/r149-security-qa-regression-matrix`. الأدلة: السجلات `270`–`281`.

## الفجوات المثبتة — أُغلقت في هذه الدفعة

الملف `tests/test_r149_security_qa_gaps.py` (20 اختبارًا). كل الحقن عبر **الطبقة الحقيقية** (`SupabaseStorage`) ضد محاكاة PostgREST محلية قابلة للتحكم عبر HTTP فعلي (أحكام لكل (طريقة، جدول): رمز رفض، قطع النقل قبل الرد، رد جزئي يُقطع أثناء قراءة الجسم، إبطاء يتجاوز مهلة العميل المقرّرة، وتمييز **بالحمولة**)، ومسجّلة منفصلة: نتيجة التنفيذ وحالة `TASKS`، الحمولات المُحاوَلة (نسخ عميقة)، ما حُفظ فعلًا، الأحداث المنشورة، وإحصاءات الطبقة.

- **G1 — فشل كتابة التخزين داخل `/api/chat` والمسار الخلفي**: كل الكتابات مرفوضة (401) ← الاستجابة 200 بعقدها الكامل وبالنتيجة الحقيقية، والذاكرة بالحالة الصحيحة، والكتابات الأربع مُحاوَلة لا مُتخطاة، ولا ادعاء حفظ في الاستجابة؛ رفض الإدراج وحده (403) ← التحديث النهائي مُحاوَل بالحالة الصحيحة؛ رفض التحديث النهائي وحده (بعد قبول الإدراج وrunning) ← الصف الدائم يبقى متأخرًا ولا يُدّعى نجاحًا محفوظًا؛ رفض الحدث النهائي وحده (بعد قبول حدث الإنشاء)؛ قطع النقل (قبل الرد، ورد جزئي أثناء القراءة)؛ مهلة نقل حتمية (مهلة العميل 0.2ث وخلفية تنام 1ث) — بلا انتظار حي. نتيجتا ok=True وok=False كلتاهما مغطاتان.
- **G2 — فشل قراءة المهمة المخزنة** (`GET /api/tasks/{id}` غائبة عن الذاكرة): 404 بنص ثابت (العقد المتدهور الحالي: فشل القراءة لا يتميز عن غياب الصف) مع تسجيل **كل محاولة** بمعاملات استعلامها — كلها تحمل `task_id` ونطاق المستأجر، ولا محاولة بلا مرشح المستأجر (لا بديل غير مقيّد)؛ وللمستأجر الآخر: محاولاته بنطاقه فقط والصف لا يظهر.
- **G3 — عدم التسريب عبر مسارات الخطأ**: علامة سرية (كلمتا سر) تمر فعلًا عبر كل مسارات الخطأ — جسم رفض الخلفية، واستثناء غير متوقع داخل وكيل حقيقي، ورفض انتقائي بالحمولة تحت الطبقة، ومهلة اعتماد داخلي — ← **لا تصل أي مكان**: لا الاستجابات ولا نتيجة المهمة ولا الأحداث ولا السجلات (بما فيها سطر فشل التخزين).
- **G4 — استثناء داخل وكيل حقيقي، ومهلة اعتماد داخلي**: `execute()` الحقيقي بلا تعديل، والمعالج الذي يستدعيه يرفع (خارج مزدوج مخالف للعقد) — المهمة تنتهي **failed** بنتيجة وحدث صادقين، لا تبقى معلقة؛ ومهلة اعتماد داخلي حتمية (`TimeoutError` من `asyncio.wait_for`) تنهي المهمة failed بنتيجة تحمل النوع فقط بلا تسريب. (ملاحظة منهجية: وكيل يخالف عقد execute نفسه بالرفع خارج معالجات الوكلاء الحقيقيين الثلاثة — خارج نطاق هذا العقد؛ عقد الوكلاء يضمن عدم الرفع وهو ما يثبته هذا الاختبار عند حدوده.)

## التسريبات الثلاث المكتشفة والمُصلحة (أصغر إصلاح)

الفشل قبل الأولين محفوظ بالسجل `270` (اختباران فاشلان + 17 ناجحًا، RC=1)، وقبل الثالث بالسجل `276` (4 فاشلين + 16 ناجحًا، RC=1 — على الالتزام الأول `a5c7a93`):

1. **محوّل الوكيل الخارجي يعكس جسم خطأ الخلفية إلى المستأجر**: `RuntimeError(f"HTTP {status}: {body[:300]}")` كان يجعل أول 300 حرف من جسم رد الخلفية نص خطأ التنفيذ — الذي يصبح نتيجة المهمة المرئية للمستأجر عبر `GET /api/tasks/{id}` وسطر السجل. خلفية معادية تردد مفتاح المحوّل الإداري (المُرسل في `Authorization`) في جسم الخطأ كانت توصله للمستأجر — مثبت تجريبيًا قبل الإصلاح («KEY IN TENANT-VISIBLE RESULT: True»). الإصلاح: السبب صار `HTTP <status>` فقط.
2. **سطر رفض التخزين يسجل جسم الخلفية خامًا**: `_accepted` كان يسجّل `(op, status, body[:300])` — جسم الرفض نص غير موثوق قد يردد مفتاح الخدمة؛ مثبت قبل الإصلاح (العلامة في السجل). الإصلاح: السجل يحتفظ بالعملية والرمز فقط (تشخيص RISK-013 يبقى كافيًا)؛ الإحصاءات لم تتغير (كانت تحفظ الرمز فقط أصلًا).
3. **نص الاستثناء غير المتوقع يصل المستأجر والسجل خامًا**: نتيجة الوكيل كانت تحمل `النوع: النص` (`real_agents.py` و`specialist_runtime.py`) وسطر فشل التخزين كان يسجل نص الاستثناء — النص غير موثوق وقد يحمل تفاصيل داخلية. الإصلاح: النتيجة تحمل **نوع الاستثناء فقط** والسجل يسجل العملية والنوع — مع استثناء ما هو سبب ثابت آمن مقصود يثبته الاختبارات القائمة وبقي كما هو: رسائل رفض `UnsafeURLError` (SEC-01/SEC-05)، وأسباب طبقة الاتصال المصوغة في المحوّل (فشل/فراغ DNS، عدم تطابق شهادة TLS، حد حلقة التحويلات)، وحالة HTTP.

## حدود الإثبات (لا يُدّعى ما دونها)

- لا اختبار اختراق حي ولا نشر إنتاجي؛ اختبارات الأمن الجديدة في هذه الدفعة حتمية محلية (اختبارات الشبكة الحية تشغيل منفصل — `275`/`281`).
- مستويات الأدلة متمايزة وليست بدائل لبعضها: وحدة الطبقة (R-082 — PostgREST وهمي) / طلب حقيقي عبر التطبيق مع محاكاة PostgREST على HTTP محلي (الجديد، BUG-02/04، SEC-02 — كلها ThreadingHTTPServer بمحاكاة سلوك PostgREST، ليست محرك PostgREST فعليًا) / اختبارات المعالجات الحية (BUG-02 مسار الوكيل الحقيقي).
- SEC-07 وBranch protection خارجا نطاق هذه الدفعة بقرار المهمة.
- بناء Docker وبناءات الويب/الجذر يثبتها CI على الرأس النهائي (غير متوفرة محليًا) — كما في R-148.
- **القبول معلق على الدمج وفحوص main على SHA الدمج نفسه** — لا يُدّعى مكتملًا قبل ذلك؛ جرد 144/144 لا يكفي وحده قبولًا.

# تسجيل مسبق — فجوة النجاح الأجوف (strategist / architect / designer / reviewer) — دفعة R-170/12

> كُتب والتُزم **قبل** كتابة أي قاعدة «ملاءمة المهمة» (task_fit) وقبل أي تشغيل. البوابة تبقى معطلة افتراضيًا (قرار المالك).

## 1. المشكلة (السجل 288)
المعالجات الأربعة حتمية؛ تعيد `ok=True` دون إنجاز الطلب (ترتيب جملة الطلب نفسها «كأهداف»، خط أساس مفترض، لوحة ألوان بدل خطوط،
«text metrics only» بلا شيفرة). القاعدة المطلوبة: **لا نجاح دون دليل قابل للاختبار على إنجاز المهمة المطلوبة**.

## 2. المدونة
`benchmarks/r170/hollow/cases.jsonl` — 244 حالة، sha256 `4a3a623fc7a88be1f3d65bcb63d37b5d0e35e271f4323b9708b72ec5e8f1988b`، يولدها `scripts/r170_hollow_corpus.py` (حتمي).
- لكل حالة **حقيقة مستقلة** كُتبت معها قبل أي قاعدة: `completable` (ما يحتويه المخرج الصحيح: الأهداف بالترتيب، المكونات،
  اللون/الثيم الأساس، عيوب الشيفرة) أو `not_completable` (المعالج لا يستطيعها ⇒ أي نجاح أجوف).
- عائلات: مهام نصية (strategist/architect/designer)، مراجعة شيفرة (reviewer: عيوب معروفة + شيفرة سليمة)، **عربي وإنجليزي**،
  `prose_correct` (إجابات نثرية **صحيحة** من تنفيذ آخر كنموذج — خطر الرفض الخاطئ للشكل)، `prose_hollow` (نثر أجوف).
- الفصل بـsha256(المعرف): dev 103، validation 59، **test 82** (48 قابلة، 34 غير قابلة؛ 48 عربية).
- إفصاح: المنفذ كتب كل الحالات (رأى test عند كتابتها، قبل أي قاعدة). التطوير والضبط على dev فقط؛ validation للفحص؛
  **test مرة واحدة** بعد تجميد الشيفرة، ولا ضبط بعده.

## 3. المقاييس (`scripts/r170_hollow_eval.py`)
النتيجة النهائية «نجاح» = `ok=True` من المعالج (العلم معطل) / و`ok=True` بعد البوابة (العلم مفعل). تُقاس الحالتان منفصلتين.
- **H1 كشف النجاح الأجوف**: حالات `not_completable` التي **لم** تنته بنجاح / كل `not_completable`.
- **H2 الرفض الخاطئ**: حالات `completable` التي انتهت بغير نجاح / كل `completable` (تشمل prose_correct).
- **H3 صحة المقبول**: من حالات `completable` المقبولة، نسبة مطابقة الحقيقة المستقلة (أوراكل في سكربت التقييم، لا يستخدم task_fit).

## 4. معايير القبول على test (Wilson 95%)
| | المعيار |
|---|---|
| H1 (العلم معطل **و**مفعل) | ≥ 90% وحد أدنى ≥ 75% (n=34) |
| H2 (العلم معطل **و**مفعل) | ≤ 1/48 (حد أعلى ≈ 11%) |
| H3 | ≥ 90% |
| عدم تراجع | تقييم مخاطر البوابة (السجل 287/288) على dev وvalidation: رفض كاذب يبقى 0 في العائلات غير النصية |
تُعرض النتائج لكل تخصص ولكل لغة ولكل عائلة، مع كل حالة رفض خاطئ ونجاح أجوف وسببها. الفشل يُنشر كما هو.

## 5. حدود معلنة مسبقًا
- task_fit **بنيوي حتمي**: يثبت أن نوع المخرج يطابق المطلوب وخصائص قابلة للفحص (عدد العناصر، اللغة، التتبع إلى الطلب،
  التباين المعاد حسابه، أسطر العيوب)، **لا** جودة المحتوى ولا صحته الدلالية. النثر الصحيح يُقبل ببنية لا بفهم.
- الحقيقة المستقلة وسوم المنفذ (ليست مراجعة بشرية؛ Q-028 منفصلة).

## 6. تعديل A1 (قبل أي تشغيل، دون رؤية أي نتيجة)
عائلتا `prose_correct` و`prose_hollow` ليستا مخرجات المعالجات الأربعة بل مخرجات تنفيذ آخر؛ مع العلم معطلًا لا يفحصها شيء
(وهذا بالضبط دور البوابة) ⇒ تُحسب في H1/H2 **مع العلم مفعلًا فقط**. مع العلم معطلًا: H1 وH2 على عائلات المعالجات وحدها
(test: 30 غير قابلة، 46 قابلة). العتبات كما هي: H1 ≥ 90% وحد أدنى ≥ 75%؛ H2 ≤ 1 رفض خاطئ.

# تعريف حالات العمل وشروط قبول الأدلة (STATUS_DEFINITIONS)

> **المرجع الوحيد** لمعنى حالات بنود ROADMAP منذ R-154 (D-066). أي تعريف آخر في ROADMAP أو PROJECT_STATE أو HANDOFF_PROMPT أو حزمة revival-scale يُقرأ عبر هذا الملف، وعند التعارض يُقدَّم هذا الملف. الفحص الآلي: `scripts/check_status_evidence.py` (خطوة «Status evidence check (R-154)» في job ‏`governance`).

## 1. الحالات الست (المفردات المسموح بها فقط)

| الحالة | المعنى | من يضعها | متى تنتهي |
|---|---|---|---|
| `planned` | بند مُدرج بقرار في ROADMAP ولم يبدأ | الوكيل/المالك عند الإدراج | عند بدء دفعته |
| `in_progress` | العمل جارٍ على فرع، لا PR بعد | الوكيل | عند فتح PR أو ظهور مانع |
| `blocked` | لا يمكن المتابعة لمانع موثق خارج قدرة الوكيل (قرار/صلاحية/سر/بيئة/ميزانية) | الوكيل | عند حسم المانع |
| `awaiting_merge` | العمل والاختبارات والوثائق والأدلة في PR مفتوحة واحدة | الوكيل | عند الدمج — **ويجب** تحويلها في الدفعة التالية (§4) |
| `done` | دُمج بـ`--merge`، ونجح CI على SHA الدمج نفسه، وسُجلت حقول الدليل كاملة ومتحققاً منها | الوكيل في الدفعة التالية للدمج | نهائية للوكيل |
| `accepted` | `done` + قبول صريح من **المالك** مسجل بقرار في DECISIONS | المالك فقط (الوكيل ينقل قراره حرفياً) | نهائية |

- **ممنوع**: أي قيمة أخرى في سطر `- الحالة:` (بما فيها `proposed` و`ready` القديمتان، و`production-ready`، و`conditionally accepted`). `proposed`/`ready` مفردات تاريخية لبنود R-001..R-150 ولا يحملها اليوم أي بند؛ ما يعادلهما الآن `planned`.
- **`conditionally accepted`** (مذكورة في `roadmaps/revival-scale/roadmap/ATOMIC_BATCH_RULE_AR.md` بند 7 و`P6_EXTREME_TESTING_AR.md`) ليست حالة مستقلة هنا: يقابلها `accepted` بقرار مالك يذكر الشروط المفتوحة في الحقل `conditions`، وما دام لا قرار فالحالة `blocked` (لا `done`) إن كان اختبار لازم للبند معاقاً بغياب سر أو خدمة أو بيئة.
- **`done` لا تعني «كُتب الكود»** ولا «نجح CI»: تعني اجتماع كل حقول §2 والتحقق منها (§3).

## 2. حقول الدليل لكل حالة

تُكتب في سطر واحد داخل البند (لبنود M8 فما بعد، R-151+):

```
- أدلة الحالة (R-154): key=value | key=value | ...
```

| الحالة | الحقول الإلزامية |
|---|---|
| `planned` | لا شيء |
| `in_progress` | `branch` |
| `blocked` | `blocker` (معرّف `Q-NNN` في OPEN_QUESTIONS أو `RISK-NNN` في RISKS)، `reason` |
| `awaiting_merge` | `branch`، `pr` |
| `done` | `pr`، `tested_sha`، `merge_sha`، `ci_run`، `ci_conclusion`، `tests`، `tests_log`، `skipped`، `untested`، `evidence` |
| `accepted` | كل حقول `done` + `accepted_by=owner`، `decision` (معرّف `D-NNN`)، واختيارياً `conditions` |

- `pr` = `#N`. `tested_sha` = الـSHA الكامل (40) لرأس الـPR الذي اختبره CI. `merge_sha` = الـSHA الكامل لالتزام الدمج على main. `ci_run` = رقم تشغيل CI على main عند `merge_sha`. `ci_conclusion` = `success` حصراً.
- `tests` = `N passed, S skipped, D deselected` كما طبعها pytest، و`tests_log` = سجل خام يحتوي هذا النص حرفياً.
- `skipped` = ما تُخطي/استُبعد **وسببه وأين يُشغَّل** (مثل: 4 R-042 live storage تُشغَّل في job ‏`storage`؛ 4 `network` في job ‏`network`). إن كان S أو D أكبر من صفر فلا يجوز أن يكون الحقل فارغاً أو «لا شيء».
- `untested` = الحدود التي **لم تُختبر** صراحةً (ولو «لا حدود معروفة — السبب»). الحقل إلزامي لأن الصمت عن الحدود ادعاء ضمني.
- `evidence` = مسار أو أكثر (مفصولة بفواصل) تحت `docs/audit/`؛ **الأول** هو سجل القبول.

## 3. ما يتحقق منه الفحص الآلي (لا مجرد وجود ملف)

`scripts/check_status_evidence.py` يرفض (rc=1) ويذكر كل مخالفة:

1. **مفردات**: أي `- الحالة:` خارج الحالات الست، أو بند بلا سطر حالة، أو بأكثر من سطر.
2. **حقول ناقصة/مشوهة** لحالة البند (§2) — صيغ `#N` و40 hex وأرقام و`success`.
3. **ربط git حقيقي لـ`done`/`accepted`**: `merge_sha` التزام موجود وسلف لـHEAD، عنوانه `Merge pull request #<pr> from`، وأبوه الثاني == `tested_sha`.
4. **كفاية الربط في الدليل**: سجل القبول (أول `evidence`) يجب أن **يحتوي** `merge_sha` و`tested_sha` و`ci_run` وكلمة `success`؛ و`tests_log` يجب أن يحتوي نص `tests` حرفياً. ملف موجود لا يذكر هذه القيم = رفض.
5. **`skipped`** غير فارغ (و«لا شيء» ممنوع حين S أو D > 0)، و**`untested`** غير فارغ.
6. **`accepted`**: `accepted_by=owner` و`decision` موجود كعنوان `## D-NNN` في DECISIONS.
7. **`blocked`**: `blocker` موجود فعلاً في OPEN_QUESTIONS أو RISKS.
8. **تناقض الدمج**: بند `awaiting_merge`/`in_progress` يحمل `pr=#N` وتاريخ HEAD يحتوي `Merge pull request #N from` في التزام **غير HEAD نفسه** ⇒ «مدموج ولا يزال awaiting_merge» (هذا ما حدث لـR-153 قبل R-154). الاستثناء الوحيد: تشغيل main على التزام الدمج ذاته (لا يمكن تحديث الحالة داخل التزام الدمج)؛ أي دفعة لاحقة تفشل حتى تُحوَّل الحالة.
9. **تزامن PROJECT_STATE**: جدول «حالة بنود M8» في PROJECT_STATE يطابق ROADMAP بنداً بنداً (لا بند ناقص ولا زائد ولا حالة مختلفة).
10. **الترتيب**: لا بند M8 في `in_progress`/`awaiting_merge`/`done`/`accepted` بينما بند M8 أسبق منه ما زال `planned` (`blocked` لا يوقف من بعده — HANDOFF_PROMPT §3).

**ما لا يتحقق منه (حدود صادقة)**: لا يستعلم GitHub API (لا رمز في البوابة) — نتيجة `ci_run` تُثبت بمحتوى سجل القبول المرفوع لا باستعلام حي؛ لا يحكم على **كفاية** الاختبارات علمياً (ذلك للمراجعة والطفرات)؛ بنود R-001..R-150 تاريخية تُفحص مفرداتها فقط (أدلتها نثرية في ROADMAP و`docs/audit/M0..M7`)؛ النص النثري في PROJECT_STATE (سجل التحديثات) لا يُفحص — المرجع الآلي هو جدول §9.

## 4. دورة الحياة والانتقالات

```
planned → in_progress → awaiting_merge → done → accepted
   ↘          ↘               ↘
   blocked ←───┴───────────────┘   (ومن blocked يعود إلى in_progress عند الحسم)
```

- قبول بند `awaiting_merge` يُسجَّل **داخل الدفعة التالية** (لا PR إغلاق مستقلة): تُضاف حقول `done` وسجل القبول (`gh pr view` + `gh run view` على SHA الدمج). الفحص §8 يمنع نسيان ذلك.
- لا يبدأ بند جديد في M8 قبل أن يصبح السابق `done` أو `blocked` (§3-10 + §8).

## 5. `production-ready` — قرار جاهزية مستقل، لا حالة

- **ليست حالة بند** ولا مرادفاً لـ`done` أو لنجاح CI أو للاختبارات المحلية.
- لا تُستعمل عبارة «production-ready» أو «جاهز للإنتاج» وصفاً للمشروع إلا بعد: (1) تقرير R-184 بقرار `GO` مدعوم بالأرقام والأدلة (اختبار قبول حي على staging مماثلة — R-182، runbooks وخطة رجوع — R-183، معايير `P7_RELEASE_AR.md`)، (2) عدم وجود مشكلة أمنية حرجة مفتوحة، (3) **قرار مالك** مسجل في DECISIONS يعتمد التقرير. `CONDITIONAL GO` يُذكر بشروطه ولا يُختصر إلى «جاهز».
- حتى ذلك: الوصف الصحيح «لم يُعلن جاهزاً للإنتاج» مع ذكر آخر حالة مقيسة.

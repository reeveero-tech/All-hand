# خطة إحياء AGOS وتوسيعها واختبارها — حزمة تسليم للوكيل

**تاريخ إعداد الحزمة:** 2026-10-17  
**المستودع المستهدف:** `reeveero-tech/All-hand`  
**الحالة:** مسودة خطة عمل مقترحة للتكامل؛ لا تعني أن المهام نُفذت أو أن أهداف السعة تحققت.

## الغرض

هذه الحزمة تصمم برنامج عمل مرحليًا لإحياء المشروع وتقوية ملفاته ومكوناته دون حذف أي ملف أو مجلد، ودمج مسارات العمل المطلوبة في منظومة واحدة، ثم اختبار الوكلاء والتنسيق والذاكرة والأدوات وجودة الإجابات والأمن والضغط بصورة قابلة لإعادة الإنتاج.

الأهداف العليا طويلة الأمد:

- القدرة على إنشاء وإدارة **10,000 وكيل** والتحقق من تنفيذ المهام عبر المسار التشغيلي المعتمد.
- تصميم نظام يقبل ويدير هدفًا قدره **1,000,000 مهمة متزامنة/قيد المعالجة** على بنية موزعة، بعد تعريف المصطلح وقياسه بوضوح. لا يُفهم الرقم تلقائيًا على أنه مليون طلب نموذج أو أداة تُنفذ كلها فعليًا في اللحظة نفسها.
- بناء سجل أدوات قابل للبحث والتوجيه هدفه **10,000 أداة فعلية مسجلة ومتحقق منها**؛ لا تُحتسب الأسماء المستعارة أو السجلات الوهمية أو الأدوات غير القابلة للتنفيذ كأدوات مكتملة.
- إخضاع كل مكون وخدمة وملف مهم لمراجعة أدلة واختبارات مناسبة، بما في ذلك الهلوسة وجودة الناتج وسلامة الأدوات والعزل واستعادة الذاكرة.
- تطبيق قاعدة دفعة واحدة غير قابلة للتفاوض: **الكود/الإعدادات + الاختبارات + الأدلة + التوثيق + خارطة الطريق + حالة المشروع + سجل التغييرات في نفس طلب الدمج والالتزام النهائي**.

## كيف تدمج هذه الحزمة في المستودع

1. افحص `main` ورأسه الحالي والـPRs وحالة CI من GitHub مباشرة قبل أي تغيير؛ لا تعتمد على هذا الملف بدل التحقق الحي.
2. **مهمة التكامل الأولى هي توثيقية فقط**: أضف هذه الخطة تحت مسار مناسب مثل `docs/governance/roadmaps/revival-scale/` مع الحفاظ على أسماء ومسارات الملفات القائمة. لا تنفذ ترحيلات ضخمة أو تغييرات تشغيل بالتزامن مع إدخال الخطة.
3. في **نفس PR** الذي يضيف الحزمة: حدّث `docs/governance/ROADMAP.md`، و`docs/governance/PROJECT_STATE.md`، و`docs/governance/CHANGELOG.md`، و`docs/governance/QUALITY.md` أو `OPERATIONS.md` إذا تأثرت تعليماتهما، وأرفق دليل الدمج في `docs/audit/` بحسب بوابة الحوكمة الفعلية.
4. سجّل مهام R-151 وما بعدها على أنها `planned` أو الحالة المكافئة في الخارطة الفعلية؛ لا تحولها إلى `done` حتى تُنفذ مع أدلتها.
5. افتح PR واحدًا صغيرًا للتكامل التوثيقي، وانتظر جميع الفحوص المطلوبة. لا تدمج إن لم تتطابق الحالة والوثائق والأدلة.
6. بعد دمج الخطة، نفّذ المراحل بترتيب الأولوية والتبعيات، ومهمة واحدة أو شريحة رأسية واضحة في كل PR. لا تجمع تغييرًا معماريًا ضخمًا غير قابل للمراجعة في PR واحد.

## تفسير الأرقام

هذه أهداف سعة وليست ادعاء بأن الموارد الحالية تدعمها. مليون مهمة مقبولة/مخزنة/قيد الجدولة تختلف عن مليون عملية LLM نشطة في اللحظة نفسها. يجب أن تعرّف الاختبارات هذه الحالات منفصلة، وتثبت الأرقام بالقياس على بيئة محددة موثقة. لا تُعلن نجاح هدف قبل إثباته.

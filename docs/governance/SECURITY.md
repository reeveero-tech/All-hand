## الوضع الراهن (مُتحقق من الكود — محدث بعد R-004 وR-041)

### المصادقة
- `APIKeyHeader(name="X-API-Key", auto_error=False)` مع `verify_api_key()` تفحص قيمة المفتاح (401 عند الغياب، 403 عند الخطأ) — مُفرضة على المسارات الحساسة منذ R-004 (تغطيتها في `tests/test_security.py`).
- `ENABLE_AUTH = bool(API_KEY)`؛ `AGOS_API_KEY` فارغ افتراضياً → وضع مفتوح ما لم يضبط المشغّل المفتاح.
- **جديد R-041**: مدخلا `AGOS_API_KEY` و`AGOS_ALLOWED_ORIGINS` موجودان في `render.yaml` كـ`sync: false` (يدخلهما المشغّل في لوحة Render؛ لا سر في المستودع). ترك المفتاح فارغاً يبقي الوضع المفتوح.

### جدول الحماية الفعلية (بعد R-004)

| المسار | فحص المفتاح فعلياً |
|---|---|
| `POST /api/tasks`، `POST /api/chat` | نعم (`verify_api_key`) |
| `POST/DELETE /api/agents/external*` | نعم (يفحص قيمة المفتاح) |
| مسارات `/civilization/*` | نعم (`verify_api_key` مُمرر إليها) |
| باقي المسارات (health/metrics/قراءة المهام) | لا (مقصود: مسارات فحص عامة) |

### حدود معروفة
- ~~الواجهة `web/` لا ترسل `X-API-Key`~~ — **أُغلق في R-101**: المفتاح يدخله المستخدم ويُحفظ في sessionStorage للتبويب فقط (لا localStorage، لا متغير بناء)؛ يُرسل في الترويسة لا في URL. الحد الباقي: أي سكربت يعمل في أصل الواجهة (XSS) يستطيع قراءة sessionStorage — الواجهة لا تحقن HTML خاماً (React يهرّب النص).

### CORS
- الافتراضي `AGOS_ALLOWED_ORIGINS` غير مضبوط = `["*"]`، ومعه تُعطّل بيانات الاعتماد (R-004: credentials header معطلة عند `*`؛ تُفعّل فقط مع قائمة صريحة). تحذير يُسجل عند الإقلاع.

### Rate limiting
- `@rate_limit` decorator؛ تخزين `request_counts: Dict[str, List[datetime]]` في ذاكرة العملية (غير مشترك بين العمليات/العقد). مفتاح العميل `request.client.host`.

### الأسرار
- `.env.example` يحتوي placeholders فقط. فحص أولي بأنماط مفاتيح شائعة على الملفات المتتبعة لم يُرجع نتائج — **ليس فحصاً شاملاً ولا دليلاً قطعياً**.
- `render.yaml` يستخدم `sync: false` للمتغيرات الحساسة.
- CI يستخدم `secrets.PYPI_API_TOKEN`.

### السياسة (مصدرها الوحيد `agent_civilization/core/safety.py`)

| المتغير | الافتراضي | الأثر |
|---|---|---|
| `AGOS_ALLOW_CODE_EXEC` | غير مضبوط | غير مضبوط: التنفيذ مسموح فقط إن ضُبط `AGOS_API_KEY`. `1`: مسموح. `0`: مرفوض دائماً |
| `AGOS_ALLOW_PRIVATE_NETWORK` | غير مضبوط | `1`: يسمح للأدوات والوكلاء الخارجيين المسجلين عبر API بعناوين داخلية |

- عزل التنفيذ عند السماح: `python -I`، بيئة فارغة (PATH/HOME/TMPDIR/LANG + متغيرا Python)، مجلد مؤقت يُحذف، حدود CPU 5ث، ذاكرة 512MB، ملف 10MB، 64 ملفاً مفتوحاً، بلا core، مهلة 8ث مع قتل مجموعة العمليات.
- العناوين: يُحظر كل عنوان غير عام (loopback، RFC1918، link-local والبيانات الوصفية، CGNAT 100.64/10، ULA، المتعدد، المحجوز، وصيغ IPv6 التي تحمل IPv4 داخلها: mapped وNAT64 و6to4)؛ نطاقات التوثيق مسموحة (غير قابلة للتوجيه).
- `GET /api/system/status` → `security.tool_policy` يعرض السياسة الفعالة (بلا أي قيمة سرية).

- `DELETE /api/memory` يتطلب `AGOS_API_KEY` مهيأً (403 في الوضع المفتوح). `AGOS_MEMORY=0` يعطّل التخزين كلياً. مع `AGOS_MEMORY_FILE` تُكتب الذكريات على القرص بنص واضح.

## R-104 — `DataWorkerAgent` معزول عن المسار (D-047، 2026-10-14)
- قبل R-104: `agents/executors/data_worker.py` بلا مستورد في المستودع كله (حتى الاختبارات) و`_process_data` يخفي فشل LLM. بعد R-104: `process_text()` مسار حي من `real_dispatcher._data_processor` لمدخل نصي فقط؛ المدخل الرقمي حتمي وغير متغير؛ فشل LLM يُنشر صراحةً (`error` مع `model`) بدل إخفائه. لا كود تنفيذ جديد ولا أسرار جديدة؛ **مسار شبكة واحد جديد**: مدخل نصي لـ`data_processor` كان يُرفض («no numeric data») صار يُرسل إلى OpenRouter عبر `get_llm().complete` (موجودة أصلاً في `core/llm.py`) — حارس العناوين لا يغطي هذا المسار (يفحص `safe_urlopen` فقط) لكن OpenRouter مزود LLM موثوق لا عنوان داخلي.
- الحزم الفارغة الثلاث (`communication/`, `runtime/`, `utils/`) أُبقيت بلا حذف — إزالتها تتطلب قرار D منفصل + فحص مستهلكين + وسم git (قواعد الفقرة 6).
## R-105 (D-049) — ملاحظة أمنية: توليد الأصناف في وقت الاستيراد
- الأصناف الخمسون لكل تخصص تُولَّد عند الاستيراد عبر `type()` من صنف أساس حقيقي واحد — **لا `exec()` ولا تقييم سلاسل** في المسار الحي (أُزيل exec القوالب في جولة المراجعة). تخطيط الأسماء/الافتراضات بيانات داخل الحزمة (`_spec_layout.py`) لا يعتمد على ملفات خارج مصدر الحزمة.
- الوحدات الـ1,000 وحدات توافق رقيقة: استيراد + `create()` فقط — لا منطق تنفيذ مكرر (يُؤكد باختبار).
- لا تغيير على سطح الهجوم: نفس الواجهة، نفس السلوك (1000/1000)، والاستيراد الفردي ما زال يعمل.
- **R-116 / D-051 (مسارات شبكة صادرة جديدة — كلها عبر `safety.safe_urlopen`، حارس العناوين R-100 يغطيها)**: `POST https://text.pollinations.ai/openai` (LLM بلا مفتاح، عند غياب `OPENROUTER_API_KEY` فقط؛ يُعطَّل بـ`AGOS_LLM_KEYLESS=0`)، `GET https://api.mymemory.translated.net/get` (ترجمة)، `POST https://html.duckduckgo.com/html/` (بحث ويب)، وفحص HTTP(S) للمضيف المطلوب في `network_client`. **لا أسرار جديدة** ولا مفاتيح تُرسل لهذه الخدمات. تنبيه خصوصية: نص المهمة يُرسل لمزود عام بلا اتفاقية خدمة عند غياب المفتاح — لبيانات حساسة يضع المالك `OPENROUTER_API_KEY` أو يعطّل المزود العام.
- **R-121 / D-052 (سياق TLS مشترك)**: `safety.safe_urlopen` يستخدم سياق TLS واحداً لكل العملية (`safety.tls_context()` = `ssl.create_default_context()` — `CERT_REQUIRED` + `check_hostname`، كالسابق) بدل سياق جديد لكل اتصال؛ التحقق من الشهادات والمضيف وحارس العناوين وإعادة التوجيه (R-100) بلا تغيير (اختبار `tests/test_r121_tls_context.py`). أثر جانبي: تغيير حزمة CA في النظام يسري بعد إعادة تشغيل العملية.
- **R-124 / R-125 / D-053**: `safe_urlopen` يقطع حلقة opener↔handler بعد كل طلب (لا تغيير في التحقق أو الحارس). `self_developer` يعيد تشغيل أهداف متذكَّرة فاشلة (حتى `AGOS_SELF_RETEST_MAX`=3، مهلة 120ث) عبر المسار الحقيقي — أي يعيد إرسال نصوص طلبات سابقة (من الذاكرة المشتركة، نفس نطاق RISK-026) إلى الشبكة/LLM عند استدعائه؛ لا يعدّل الكود ولا يكتب ملفات؛ `AGOS_SELF_RETEST_MAX=0` يعطّل إعادة الاختبار.
